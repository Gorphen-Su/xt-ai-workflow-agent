# 上下文隔离策略

本文档定义 xt-sdd 所有阶段共享的上下文隔离策略，防止长任务流挤爆上下文导致任务运行一半停止。

## 核心认知

**AI 不能主动触发 `/clear`**（它是用户级 CLI 命令）。可行路径：

1. **Subagent 隔离**（AI 用 Agent 工具主动调用）← 最强大
2. **建议用户 `/clear` + 断点恢复**（AI 提示，用户执行）
3. **依赖自动压缩**（Claude Code 内置 compact，兜底）

---

## 策略 1：Subagent 隔离执行（核心）

### 原理

用 Agent 工具启动 subagent，subagent 有**独立上下文窗口**，执行完只返回摘要给主对话。

```
主对话（轻量，只协调）
  ├── Agent 工具 → subagent A 执行任务 1（独立上下文）
  │                  ↓ 返回摘要（状态+结果）
  ├── Agent 工具 → subagent B 执行任务 2（独立上下文）
  │                  ↓ 返回摘要
  └── Agent 工具 → subagent C 执行任务 3（独立上下文）
```

### 优势

- ✅ 主对话上下文几乎不增长
- ✅ 每个任务完全隔离，互不干扰
- ✅ AI 可主动调用，无需用户干预
- ✅ 天然防挤爆

### Subagent 调用模板

```
使用 Agent 工具启动 subagent 执行此任务：

subagent 任务：执行 TDD 任务 N（RED → GREEN → REFACTOR）
subagent 输入：
  - 任务描述：<从 tasks.md 读取>
  - 相关 spec：<仅当前 capability>
  - 计划文件：<当前分组 plans/NN-*.md>
  - 技术栈：<compile_command, test_command>

subagent 完成后，主对话仅接收：
  - 任务状态（completed/failed）
  - 测试结果摘要（pass/fail 计数）
  - 修改的文件列表
  - 规范偏离说明（如有）

主对话更新 sdd-state.yaml，触发下一个 subagent。
```

### 适用场景

| 阶段 | 隔离单元 | 收益 |
|------|---------|------|
| apply | 每个 TDD 任务 | ⭐⭐⭐ 最高 |
| verify | 每轮审查 | ⭐⭐ 高 |
| plan | 每个分组的 writing-plans | ⭐⭐ 高 |
| propose | 每个 artifact 生成（可选） | ⭐ 中 |

## 策略 2：阶段切换时建议 `/clear`

### 原理

每个阶段完成后，状态已存 sdd-state.yaml，建议用户 `/clear` 后进入下阶段。

```
propose 完成 → 状态存盘 → "建议运行 /clear，然后 /xt-sdd:plan"
                              ↓ 用户执行 /clear
plan 从 sdd-state.yaml 恢复 → 执行 → 完成 → "建议 /clear，然后 /xt-sdd:apply"
                              ↓
apply 从 sdd-state.yaml 恢复 → ...
```

### 阶段完成提示模板

```
✓ <阶段名> 阶段完成

所有进度已保存到 sdd-state.yaml：
- phase_checkpoints.<阶段>: done
- checkpoint: done

【建议】运行 /clear 清除上下文，然后运行 /xt-sdd:<下一阶段> 继续下阶段。
（断点恢复机制确保从正确位置继续，无需担心丢失进度）
```

### 优势

- ✅ 阶段间完全隔离
- ✅ 每阶段从干净上下文开始
- ✅ 配合已有的断点恢复机制

---

## 策略 3：任务批次 + 强制 `/clear` 提示

### 原理

长任务流（如 apply 的 N 个任务）按批次划分，每批次完成后提示 `/clear`。

### 批次划分规则

| 任务数 | 策略 | 批次大小 |
|-------|------|---------|
| ≤ 3 | 连续执行，无需 /clear | - |
| 4-6 | 建议用 subagent 隔离 | - |
| > 6 | subagent 隔离 + 每 5 任务提示 /clear | 5 任务/批 |
| > 6 + 小窗口模型 | 强制每 3 任务提示 /clear | 3 任务/批 |

### 批次完成提示模板

```
✓ 已完成批次 X（任务 N-M）

进度已保存到 sdd-state.yaml：
- 最后完成任务: M
- checkpoint: task-M-complete

【建议】运行 /clear 清除上下文，然后重新运行 /xt-sdd:apply
（将从任务 M+1 自动恢复）

或继续执行下一批次（不推荐小窗口模型）。
```

### 触发条件

- 任务数 > 6（大窗口模型）
- 任务数 > 3 且为小窗口模型
- 估算上下文用量 > 60%

---

## 策略 4：自动压缩兜底

### 原理

Claude Code 内置 compact（接近满时自动压缩为摘要）。配合 sdd-state.yaml 实时存盘做兜底。

### 配合规则

- **关键状态实时写入 sdd-state.yaml**（每个任务/步骤完成后）
- 即便被压缩，也能从 sdd-state.yaml 恢复
- 断点恢复机制（resume-check.sh）验证文件一致性

---

## 组合方案

```
┌─────────────────────────────────────────────────┐
│  阶段间：策略 2（/clear + 断点恢复）             │
│    propose 完成 → /clear → plan                  │
├─────────────────────────────────────────────────┤
│  阶段内重任务：策略 1（subagent 隔离）           │
│    apply 每个 TDD 任务 → 独立 subagent           │
│    verify 每轮审查 → 独立 subagent               │
│    plan 每个分组 → 独立 subagent                 │
├─────────────────────────────────────────────────┤
│  长任务流兜底：策略 3（批次 /clear 提示）        │
│    任务数 > 6 时，按批次提示 /clear              │
├─────────────────────────────────────────────────┤
│  全程兜底：策略 4（自动压缩 + sdd-state 存盘）   │
└─────────────────────────────────────────────────┘
```

---

## 决策流程

```
开始执行任务流
  ↓
任务数 ≤ 3？
  ├── 是 → 连续执行（策略 4 兜底）
  └── 否 ↓
        小窗口模型？
          ├── 是 → subagent 隔离（策略 1）+ 每 3 任务 /clear（策略 3）
          └── 否 ↓
                任务数 > 6？
                  ├── 是 → subagent 隔离（策略 1）+ 每 5 任务 /clear（策略 3）
                  └── 否 → subagent 隔离（策略 1）
```

## 预期收益

| 场景 | 原方式 | 隔离后 | 改善 |
|------|-------|--------|------|
| 10 任务 apply | 主对话累积爆掉 | subagent 隔离，主对话轻量 | 100% 不爆 |
| 5 轮 verify 审查 | 累积易爆 | 每轮独立 subagent | 100% 不爆 |
| 跨阶段长流程 | 全程累积 | 阶段间 /clear | 每阶段干净开始 |
| 小窗口模型 | 30% 成功率 | 隔离 + 批次 /clear | 90%+ 成功率 |
