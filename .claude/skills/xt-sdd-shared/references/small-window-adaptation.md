# 通用小窗口模型适配

本文档定义 xt-sdd 所有阶段共享的小窗口模型适配策略。

## 目标

解决小窗口模型（glm-4.7、deepseek-flash）的上下文限制问题：
- 上下文窗口：8k-32k tokens（vs Claude 的 200k）
- 长对话容易中途爆掉
- 执行状态会缺失，导致无法恢复

**预期收益**：成功率从 30% → 80%

---

## 模型检测

### 检测逻辑

通过环境变量检测当前使用的模型：

```bash
is_small_window_model() {
  case "${MODEL_NAME:-}" in
    *glm*4*|*glm-4*|*deepseek*flash*)
      return 0  # 小窗口模型
      ;;
    *)
      return 1  # 大窗口模型
      ;;
  esac
}
```

### 小窗口模型列表

| 模型 | 上下文窗口 | 特征 |
|------|----------|------|
| glm-4-plus | ~128k | 较大，但仍需优化 |
| glm-4-air | ~128k | 较大，但仍需优化 |
| glm-4-flash | ~128k | 较大，但仍需优化 |
| deepseek-chat | ~32k | 小窗口 |
| deepseek-reasoner | ~64k | 中小窗口 |

## 轻量模式

### 模式对比

| 特性 | 标准模式 | 轻量模式 |
|------|---------|---------|
| 指令详细度 | 完整说明 | 精简到核心 |
| 历史保留 | 完整对话 | 仅 2-3 轮 |
| 清理频率 | 每 5 步 | 每 1-2 步 |
| 检查点保存 | 步骤完成 | 每个子操作 |
| 输出详细度 | 完整输出 | 摘要式 |

### 自动触发条件

```markdown
**轻量模式自动触发**：
1. 检测到小窗口模型（MODEL_NAME 包含 glm-4、deepseek）
2. 上下文已使用超过 40%（如果能检测）
3. 已完成 3+ 个步骤
```

---

## 紧急清空触发

### 触发条件

当满足以下任一条件时，触发紧急清空：

1. **已完成 3-4 个步骤**（小窗口模型）
2. **已使用超过 60% 的上下文窗口**（如果能检测）
3. **即将执行高 token 消耗操作**（如 skill 调用、批量生成）

### 清空后行为

```
[上下文清空]

已保存进度到 sdd-state.yaml：
- checkpoint: <当前检查点>
- last_action: <最后执行的动作>
- current_objective: <下一步目标>

可忽略之前的详细对话，继续执行：
→ <下一步骤>
```

## 各阶段应用要点

| 阶段 | 关键风险点 | 适配策略 |
|------|----------|---------|
| propose | openspec-propose 生成 4 个 artifacts | 每个 artifact 后清空 |
| plan | 按 N 分组调用 writing-plans | 每个分组后清空 |
| **apply** | **TDD 循环多任务累积** | **每个任务后清空（最关键）** |
| verify | 审查循环多轮 | 每轮审查后清空 |
| quick | 复用 apply | 同 apply |
| archive | 相对简单 | 低风险，按通用规则 |

## 中断恢复增强

### interrupt_guard 结构

小窗口模型场景下，建议在 sdd-state.yaml 中增加中断保护：

```yaml
interrupt_guard:
  last_successful_checkpoint: <最后成功的检查点>
  in_progress_step: <执行到一半的步骤>
  in_progress_action: <正在执行的动作>
  model_type: small-window
  interrupted_at: <ISO 8601 时间戳>
```

### 恢复逻辑

重新运行时：
1. 读取 `interrupt_guard.model_type`
2. 如果是 `small-window` 且有中断
3. 显示："从中断点恢复：checkpoint = <in_progress_step>"
4. 直接从中断步骤继续，而非从头开始

## 输出精简（轻量模式强制）

检测到小窗口模型时，所有输出自动使用精简格式：

| 类型 | 精简格式示例 |
|------|------------|
| Git 状态 | `Git: 2M, 1A → 脏状态` |
| CLI 调用 | `状态: proposal ✓, design pending` |
| 测试结果 | `测试: 15/15 通过` / `测试: 13/15 失败` |
| 编译结果 | `编译: ✓ 通过` / `编译: ✗ 失败` |
| Artifact | `✓ proposal.md 创建` |
