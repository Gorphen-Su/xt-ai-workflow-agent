# xt-sdd2 · explore — 需求挖掘阶段

**REQUIRED SUB-SKILL:** 使用 grilling 引擎执行追问循环（本技能只规定纪律与产物格式，发问方式全权交给 grilling）。
**共享约定：** 读取 [.claude/skills/xt-sdd2-shared/SKILL.md](../xt-sdd2-shared/SKILL.md) 与卷宗结构。

## 铁律

1. 本阶段只产出 grill.md，MUST NOT 写生产代码、design、tasks 或 proposal
2. 决策登记册 MUST 边谈边填：每得到一个结论立刻写入文件，禁止"聊完再整理"
3. 第一轮对话内完成变更类型分诊：feature | bug | chore
4. 结束条件 = 开放问题清零，或将每条显式降级为假设写入登记册
5. 结束 MUST 用户确认

## 步骤

### 0. 前置检查
- `openspec/project.md` 存在？无 → 引导先跑 `/xt-sdd2:init`
- Git 工作区脏 → 先询问是否提交/搁置（污染卷宗归属）

### 1. 分诊
- bug → 追问补齐三必答：复现步骤 / 根因假设（标置信度）/ 修复边界
- feature/chore → 进入正常挖掘
- **快速通道**：若用户输入已自含全部关键决策的小型变更，可用一轮登记闭合——但 grill.md 文件照样创建、登记册照样成文。快在对话轮数，不快在工件

### 2. 挖掘（grilling 引擎主持）
- 允许中途做 codegraph_explore 侦察存量代码，把关键发现（符号、调用链、隐性约束）记入"关键问答摘录"
- 每问一闭环：问题 → 结论 → 当场入册；影响到的 R-ID 此刻未知则留空（propose 回填）

### 3. 闭幕
- 开放问题清单全部处置完毕
- 生成卷宗目录 `openspec/changes/YYYY-MM-DD-<缩写>-<slug>/`（创建前扫描重名），从模板复制 [grill.md](../xt-sdd2-shared/references/templates/grill.md) 填充
- 展示登记册摘要 + 假设清单 → **AskUserQuestion 确认后**提示进入 `/xt-sdd2:propose`

## 理性化防御表

| 诱惑 | 现实 |
|------|------|
| "用户忙，先聊完回头补档" | 事后整理会混入你的重构和遗忘——未加工原话正是证据链最值钱的部分 |
| "这需求太简单不值得留档" | 留档成本 = 复制一份模板填五行；未来审计者没有你的记忆 |
| "需求很明确，跳过提问直接起草 proposal" | 明确感的来源恰是需要被捕获的假设；把你的默认值写成登记册的一行让用户签字 |
| "用户说'别管流程'就裸奔" | 快速通道已经是最小合规形态；再砍只剩口头约定，出了争议无凭无据 |

## 红旗 — 出现即停下纠正

- 对话进行多轮后 grill.md 还不存在
- 登记册里出现"应该是""大概"这类未标注【假设】的措辞
- 开始讨论具体实现方案或技术选型（那是 design 的职责）
